# 已归档图片与视频清理

入口：设置的「图片与视频存储」，以及真实媒体／我谕工具菜单的「清理归档附件」。可选择单个角色、独立剧情或全部范围。先扫描数量与附件体积，再由用户确认；不调用模型。

角色消息必须同时满足：无群聊归属、ID 不超过可靠记忆处理水位、严格早于 hideBeforeMessageId。当前手动上下文明确重新纳入的消息受保护。执行前在事务内重读角色、水位和实际消息，消息内容／资源已改变则跳过。

独立剧情必须同时有 theaterArchived 标记，以及 story_theaters 中覆盖该消息的已保存事件盒或向量归档范围。只有标记、没有成功记录不清理。

只处理原生 image 消息及 metadata.realMedia。视频连同原片和截帧解除引用；消息改为可读文本，保留发送时的文字、时间、来源、视觉描述和 mediaCleared 标记。表情、音频、记忆节点、相册均不被修改。

消息修改、全引用面检查及候选 Blob 删除处于同一 IndexedDB 写事务；扫描或存储失败整体回滚。引用面包含现有 REF_SOURCE_STORES、造物间各表与剧情条目，另检查 localStorage。相册、收藏、转发、头像或其他记录还在使用的文件保留；不删除无关孤儿文件。

预览体积按本地候选文件去重，实际释放空间可能更少。清理后的新备份沿用现有消息 JSON 与 Blob 收集机制，不再携带已解除的独占资源；共用资源仍保留。已经下载的旧备份不改变，导入旧备份仍可能恢复旧附件。
