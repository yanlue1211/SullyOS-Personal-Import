# 离开后消息（定制 B 方案）

本仓库只对 **离开后自动空闲提醒** 实行定时循环：2.0 以角色最后一次聊天发言为锚点，每经过设定间隔（30分钟至6小时）给角色一次主动找人的机会；用户单独发消息、角色未回复时不推迟。原作者 2.0 关闭时的逻辑不变。独立的角色自主预约消息和用户手动排程均不受空闲提醒睡眠禁发及线下状态锁影响。

**此文档描述测试分支代码，正式 Worker 尚须实际部署和端到端验证。**

## 入口及 API
- 聊天「＋」→「离开后消息」：每角色空闲间隔、睡眠禁发区间。
- 聊天「＋」→「预约消息」：Char 自主预约以及用户手动预约任务的独立设置、额度、清单。关闭预约消息不会关闭云端离开后消息。
- 「预约消息」内的「独立 API」：每角色单独设置定时任务使用的 URL、Key、模型。**离开后云端消息也复用这套 API**；启用但缺字段时**不回退**昂贵主模型；普通聊天及聊天中的工具调用仍使用原聊天 API。
- 离开后功能开启、全局 Worker 已配置且云端代码版本匹配时，由云端独立排程，**不要求角色开启预约消息**；没有云端 Worker 的角色走本地逻辑，只有重新打开/切回前台才检查。

## 云端循环规则
1. 客户端在普通聊天时按最新角色消息时间核对远端任务；没有新的角色回复不更改锚点，避免用户单独留言推迟节拍。快速连续同步只保留最新角色锚点，防止并发双建任务。在前台启动时只补缺不抢已有未来节拍，后续前台恢复按至少 15 分钟间隔再次检查失联链条；这不是后台定时轮询。
2. Worker 认 `amsgAwayMessage` 标记，先校验开关、最新用户时间；未到点只 defer，不生成。
3. 到点在 **调用任何大模型之前**创建下一条一次性任务；UUID 根据当前节拍和角色确定，重复执行不会重复创建。严重迟到时跳过所有已错过时段，只排一个未来节拍。
4. 禁发时段内到点的离开后机会延至用户当地解禁时刻（例 07:50→08:00）；续排从解禁时间开始计间隔。等待中 **0 次 LLM 调用**。全天禁发与线下见面 / 通话仍静默跳过；旧的过期节拍不批量补发。自主预约不受此规则影响。
5. **预约与离开后消息独立核算**：自动离开提醒有自己的每日发送/模型调用账本，不扣预约的连发与每日额度；关闭预约开关不拦离开后链条。Char 自排和用户手动预约仍遵守预约专属规则。
6. 禁用离开后消息会写入云端小型 limits 禁发闸，并取消可辨识的远端空闲链。设置变更会先阻断旧异步重排，再等待在途任务落定、按最新设置处理；即使先前取消失败，关闭状态下重新保存也允许重试清理残留任务。**只取消带离开后标记的任务，不取消预约**。
7. Worker 任务继承模型凭据；到点生成走定时任务独立API，不改普通聊天生成模型。

## 线下及通话
- 进入和显式结束 DateApp / CallApp 时，先更新持久标记并立即发送小型云端状态，随后打脏并刷新大包快照。
- 切后台、杀应用不会自动判定线下或通话结束。显式退出见面才解除见面标记。
- 线下保护只针对标记为 `amsgAwayMessage` 的自动空闲提醒。角色约定明早06:30来信属于自主排程，不经过这些新拦截门。

## 本地备用
- 只检查「最后一次用户消息+N个间隔」中**当前最近一个**节拍，上次同节拍已生成则不重复。
- 有禁发、正在见面/通话或当前正在与角色互动则跳过，生成过程中用户回来则放弃写入。
- 仅一次生成，按当前时间落库；不为整夜错过的时段伪造多条历史消息。
- 被允许生成时也走定时任务专属 API；错误后短暂冷却，避免反复请求。

## 修改范围
- `utils/awayMessage*.ts`：计时、睡眠区间、前后端本地逻辑。
- `utils/amsgLimits.ts`：小型云端开关、禁发和线下锁。
- `worker/amsg/src/index.ts`：到点重排、过滤和生成。
- `utils/characterApi.ts`、`utils/amsgLlmCredentials.ts`、`utils/activeMsgClient.ts`：定时专属凭据、云端任务同步。
- `apps/DateApp.tsx`、`apps/CallApp.tsx`：线下与通话状态接缝。

不修改记忆提取、记忆召回、权重、Lite、多用户空间。正式启用前必须测试 Cloudflare 真机后台、凌晨禁发、六点半自主预约、错误重试与重复任务。

## 安全发布边界
- 新前端检测不到同版 Worker 时，**不创建 B 模式云端循环任务**，也不转用昂贵的主 API 生成假离线消息；旧任务保留。只有 Worker 确认匹配后，前端才允许自动建立空闲任务。
- 个人版前端不会在版本不符时盲目调用旧 Worker 的自动覆盖接口，因为旧 Worker 可能仍从非个人仓库下载代码。必须确认 Cloudflare `AMSG_BUNDLE_URL` 来源，使用个人版真实 Worker bundle 安全升级。
- 新个人 Worker 的默认自更新来源对应 `personal/audio-listening`，原有 `AMSG_BUNDLE_URL` 显式配置仍优先生效。首次切换前应检查来源、密钥及 D1 绑定，不允许自动清空旧任务。
