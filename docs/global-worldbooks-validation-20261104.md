## 真实请求与账单边界

在用户明确授权下使用完整角色请求进行非流式测试，不写入用户聊天。相同角色首次写入 21,091 tokens，随后读取 21,091；另一个角色重复读取 30,152。此前隔离诊断中出现 10,313 的共同前缀读取。共享前缀约 9,786 字符、诊断 token 约 10,323（带隔离标记）。这些是部分成功样本，不能代表每次跨角色都命中。

同一中转交替返回原生独占普通输入口径与转换后包含缓存的输入口径。转换形态可读到 27,964 缓存，也可全零；新旧排列均出现全零。仅凭这些返回不能归因于断点数量、确认网关路由原因或保证跨角色复用。没有为迎合中转而删除已有缓存断点，也没有自动重发正常角色请求。前台统一计数按已观测显式字段处理，原始 usage 保留。

用户账单核对：37,329 总输入、64 输出从无缓存 $0.150596 到读取 30,152 后 $0.042048，单次下降 72.1%；不能把该样本外推为长期节省比例。256 token 上限的两轮完整正常输出成功结束；64/96 token 诊断有意截断，不计为表达完整性通过。迁移前后样本均能回应用户主题，但有限样本不能证明所有角色表达完全等价。

此功能提供共享排列与控制能力；生产中继承开启状态以用户操作或导入迁移副本为准。不会把旧书静默转成全局。
