# 见面画面挂起与普通排程的语义判断

基线：个人生产分支 `2b8a23fc`。参考作者 PR #828（`7946a2d`、`03889c9`，主分支合并 `2805417a`）。

采用作者的进程内见面快照：播放位置、立绘键、观测、文字草稿与正在生成的 Promise 一起挂起。恢复同一场次不重复发送请求；已回来的新回复从数据库读回。显式结束、系统返回结束仍走原退出。刷新/杀进程不承诺恢复内存快照。线上发言或已投递的角色预约结束见面后，旧快照不能恢复该场次。

不采用作者的 date 心跳直接作废普通任务，离开提醒按用户后续要求作为独立开关接入，默认关闭；只有显式开启才有提醒任务/计时。切应用、锁屏和现实时间间隔不等于剧情分开。原来的持久见面锁仍只硬拦系统空闲机会；保留今天的安静时段边界修复、零 LLM 跳过与自动续排。

普通 expire 排程仍用现有一次生成、原生 `[[SILENT]]` 出口。Worker 从最新 limits 取见面状态，附到动态尾段（旧 fire_pack 也生效），要求对照最新共享对话判断是否仍面对面；仍在一起不发，已有合理离开计划（如六点半出门报备）可决定分开后发，不得为发消息临时虚构离开。没有额外判断 API。明确 force、即时聊天、固定内容与后台作业保留原契约。

普通排程如果选择发出可见线上正文，沿用既有场次身份校验，在真正推送成功/可靠 outbox 后才结束那场见面。静默、失败、仅工具/卡片不结束；携带旧 encounter 的任务不解锁新场次。模型语义判断并非硬性保证，测试只验证上下文传递、受控模型输出处理与状态边界。

不改记忆提取/总结/召回、数据库 schema、Lite、聊天共享历史范围或缓存前缀。不新增持久快照进备份。


可选提醒沿用作者默认关闭、1—60 分钟、默认 5 分钟的设置和本地/云端二选一路由。个人版 `isAwayCloudRoute` 实际绑定 B 方案开关，因此提醒独立按角色 2.0 开关选路，不要求用户同时打开离开后消息。旧 Worker 版本不兼容时不建任务、不发 date 心跳，也不偷偷回退本地。提醒与普通排程共享一次上下文生成基础件，但本地提醒使用独立适配文件，未重构已有 B 方案或原生离开后消息生成。

提醒不结束持久见面锁；关闭提醒/已结束见面的小型 limits 状态在生成前与推送前各检查一次，取消请求失败也尽量不送出旧提醒。提醒不占普通排程名额，生成时不提供排程工具，一次离开只找一次。开启时才将界面离开解释为这次提醒的触发条件；关闭时完全不触发。


验证：918 项相关回归通过，生产构建通过（Node 堆上限 6 GiB；首次默认 2 GiB 构建在压缩阶段 OOM，增加堆后通过）。覆盖普通预约在新鲜 date 心跳下仍可发、静默不结束见面、实际送达才结束同场次、旧场次不关闭新场次、提醒关闭/结束零生成、在场推迟、返回时取消推送、旧 Worker 不启用心跳、挂起画面与草稿恢复、未完成回复防重复、缓存与既有离开后消息。未调用用户付费模型。

Worker 成品版本：`2026-11-11.3`。网页发布不代表云端 Worker 已升级；旧 Worker 需要通过既有个人来源的原位更新，再用 `/config-check` 核对版本。

接力修复：普通见面加号菜单新增「暂离 · 保留见面」，回桌面沿用原快照，不解除见面锁。「结束见面」仍在同一菜单。剧情的真实时间陪伴原先没有调用见面锁，现按参与角色接入既有持久锁，并提供暂离/结束按钮；返回剧情列表、打开设置或切应用不解锁，重新打开同一剧情复用场次。虚构剧场不接锁。显式结束仅能解除当前剧情自己的场次，不能结束后来开启的其他见面。

排程覆盖核对（2026-11-11 接力）：普通见面发送链路原有预约能力；剧情真实时间陪伴此前缺少提示、文本工具解析与保存，现在与普通见面共用 `utils/inPersonScheduling.ts`。使用现有工具桥和云端保存，最多整轮两条、每角色独立累加，继承原频率/权限校验，任务携带各自场次 ID，预约本身不结束见面。多人必须明确参与者 ID，未开 2.0、虚构剧场、重掷和已结束/被替换的场次不执行。执行语法在显示及中央/角色镜像落库前移除；重掷不新增预约，不取消已有任务。未增加模型请求或修改记忆逻辑，Worker 无新增改动。
