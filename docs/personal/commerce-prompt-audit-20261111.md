## 顺序与缓存判断

主布局与作者一致：按位置排列的世界书、人设、用户、印象及记忆 → 聊天与功能规则 → 原顺序历史及深度世界书 → 动态召回、实时状态及尾部回应原则。个人增加全局世界书挂载、口语补充、心声、媒体、朋友圈、造物间、商城等；没有为跨角色缓存前移人设或世界书。历史系统记录用显式来源标记识别为固定历史，继续允许后续历史参与缓存。

当前Anthropic原生转换保留完整system、最近稳定历史、较早历史及工具断点；最多4个断点，不缓存动态状态之后的续答。TTL由现有设备设置统一选5m或1h，本次不改为混合TTL。可以在真实用量证实写入/读取和调用间隔后再评估固定层1h、历史5m；需满足长TTL在短TTL之前（工具→system→messages）的规则。仅重排无法保证中转渠道命中。缓存减少处理成本，不会让模型可见输入变短。

参考官方文档：[Anthropic缓存](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)、[Gemini缓存](https://ai.google.dev/gemini-api/docs/caching)。本次没有更改缓存代码、时间或世界书/记忆位置，也没有实施付费缓存测试。

## 已做与暂不做

已做商城两阶段：普通聊天不带商品；明确决定选购后查询本地目录，原完整上下文加本轮结果再续答，每次8件、最多3次查询。48件合成商品样例，常驻段从2,970降为约266字符（最终措辞会略变）；商品200件时仍维持短说明，同时不再只能买到前48件。仅查询不创建订单，订单事务继续验证权限及商品有效性。

不删世界书、记忆和历史，不自动关语音/HTML/心声，不删除用户的心声追加提示词，不改缓存断点。主要进一步空间在真实配置的历史范围、已充分转文字的历史图片是否还要每轮视觉重读，以及按需功能规则；须结合使用效果决定。表情名称和关键协议虽可变短，但直接删可能破坏现有表情和心声格式，当前不动。
