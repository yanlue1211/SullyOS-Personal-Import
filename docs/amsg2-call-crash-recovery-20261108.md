# 通话被系统杀后台后的离开后消息保护（独立修复）

案例：2026-11-08 22:19 的云端空闲机会被标为「仍在通话」，但上一次通话实际在前一天被 HarmonyOS 杀进程，用户没有机会手动挂断。原客户端使用无时效 `sully_amsg2_call_active_v1=true`，并把 `awaySceneLock=call` 持久上传，旧 Worker 会一直拦截。

## 本 PR 范围

- 只改离开后消息对通话存活的判断，**不会修改真正的语音/视频通话收音、TTS、通话记录和任何记忆逻辑**。
- 运行时的通话状态改用当前 JS 实例内存记录。切到桌面、锁屏并未重启 JS 时仍保持；完整杀进程后不会把旧 localStorage 布尔值误当成活跃电话。
- 正在通话的角色写入原有 `client_state` 里单独的 `call_presence_v1` 轻量记录，最多每 4 分钟心跳一次（仅通话时，非空闲轮询，不调模型）。
- Worker 只有见到角色匹配且 30 分钟内的真实通话心跳才拦离开后提醒；旧版无租约、进程已死或心跳过期均自动解除 **call** 锁。
- **date / 见面 / 剧情仍按原来的持久会话规则**，锁屏、后台切换、过夜不自动结束。Char 自己预约不受离开后限制。
- Worker 版本从已上线的 `2026-11-08.10` 提升为候选 `2026-11-08.11`，需网页和现有 Cloudflare Worker 配套升级；不换 D1、Token、Cron、Push，不删任务。

## 边界和费用

这不是精确判断设备被系统杀进程的 OS 事件。Web 环境在运行端无法可靠收到杀进程通知，所以只使用有限时效的心跳；如果手机真实通话持续在后台但系统暂停 JS 定时器超过 30 分钟，也可能暂时当作通话已结束，需要真机验证 HarmonyOS 的后台保活行为。必要时适度延长 TTL，不应改动独立预约或线下见面保护。

仅正在通话、已开启云端离开后提醒的角色额外写小型 Worker 状态，每小时理论上约 15 次（4 分钟一轮），不消耗 AI Token；关掉通话后停止续租。

## 发布前验证

必须测试：① 前台正常通话拦离开后但预约照常；② 切后台 5～15 分钟持续通话；③ 整个 PWA 被系统强杀后旧 call 锁最终过期；④ 昨天遗留的 `limits.awaySceneLock=call` 但无 lease 时不会被认为仍在通话；⑤ 显式挂断立刻上传 inactive，挂断记录落库失败也能清理锁；⑥ 线下/剧情独立长效锁仍正常；⑦ 已有离开后任务原位续排、无双建；⑧ 低频心跳单角色，不跨角色同步；⑨ Worker bundle 与源码、前端期望版本一致。

PR 保持 Draft、不自动合并、不自动更新线上 Worker，直到自动 CI 全绿并经手机验收。
