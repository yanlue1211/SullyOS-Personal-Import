# 回应状态与录音编辑修复

正常私聊允许角色选择已读不回或忙碌卡，使用 `<回应状态>` JSON，kind 为 read/busy。原生 React 渲染，不依赖 HTML 卡片开关或 checkbox ID。已读卡原因默认折叠；忙碌卡预计有空时间是描述，不创建定时任务、不保证届时回复。

后处理在购物、工具、日程和心声处理之前识别合法状态卡，保存一条 assistant score_card 后结束本轮，丢弃多余台词与指令。状态卡不附心声。流式预览抑制控制内容，通知只显示简短状态；历史和总结以可读文本保留已读/忙碌区别，内情标记为未说出口，忙碌不算已读。

录音识别完成后发送时，字幕和语气随消息首次保存。尚未完成的识别与背景落库、聊天上下文共用同一个 promise，完成后通过 personal-recording-edited 更新气泡。人工修正不能被晚到结果覆盖。MessageItem memo 比较包括字幕、分析、识别说明及音频清理状态，避免必须离开会话才能刷新。

自动回复 hook 独立接收 mediaComposerOpen。真实录音、录音预览、虚拟语音、图片和视频编辑都被整个媒体面板生命周期挡住，面板关闭后重新等待完整两秒。倒计时取消与新消息重置沿用原逻辑。

## 长按修改

心声胶囊、已读不回与忙碌卡片可长按或右键打开修改菜单，分别编辑结构化字段。状态卡同事务更新 content JSON 与 metadata.responseStatus；心声只更新 metadata.innerVoice，不改变公开台词。保存后通知当前聊天即时刷新；录音、主动消息规则与卡片类型保持原样。通话中已落库的心声也使用同一编辑入口。

造物间的创作回复和游戏交流回复均支持长按修改／重新回复。修改同事务写回 workroom_turns 和已投递的聊天消息，保留消息 ID、时间和其他字段。重新回复复用正常角色上下文与记忆召回，只替换公开文字，不重放动作、不重抽结果、不修改代码或游戏进度。失败、截断或并发覆盖冲突均保留原回复。存储仍是原有字段，完整备份直接保留新版内容；既有长期记忆不在编辑时自动重写。
