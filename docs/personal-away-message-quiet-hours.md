# 离开后消息：禁发时段与线下见面保护（待上游同步后接线）

当前开发分支来自 personal/audio-listening。上游 qegj567-cloud/SullyOS 在 2026-11-07 新增“离开后消息”，本分支**尚未同步该功能**；本提交只准备可共享、可单测的判定模块，**不代表已经启用**。

## 产品语义

- 独立于主动消息 1.0 / 2.0 已有的排程，属于每个角色的“离开后消息”配置。
- 配置入口拟放在「聊天 + → 离开后消息」，新增禁发时段开关和开始/结束时刻；默认关闭，开启后默认 23:00–08:00。
- 使用**用户时区**；允许跨午夜；边界左闭右开。开始等于结束代表全天禁发，UI 应明确标注。
- 在禁发期间到点的任务直接跳过，不推迟到清晨；本地下次上线补发时检查“原本到点”和“当前时刻”，不补昨夜禁止发送的消息。
- 用户和角色处于**尚未结束**的线下见面 / 剧情、或正在通话 / 真实陪伴时，必须先过独立会话状态闸。仅仅若干小时未发言不能推断“用户已离开”。离开后消息只能是线上私聊，不改变线下剧情状态。

## 需要在上游合入后连接的位置

1. types.ts 的 CharacterProfile.awayMessage 扩展 quietHours 配置，不挤占 1.0 的 proactiveConfig。
2. AwayMessageSettingsModal.tsx 显示开关和 HH:mm，默认关闭，不给已有角色修改行为。
3. 云端：创建任务 metadata 时附上 quietHours；**Worker onBeforeFire** 在实际 LLM 请求前读出，并以 `fire_pack.userTzId` 为主调用 `shouldSkipAwayForQuietHours`。任何 quiet hit **skip**，不可 defer，也不可让 force 绕过。
4. 本地：在 generateLocalAwayMessages 发请求前调用同一函数（原定 due = lastUserAt + delay），命中直接不调用 LLM；实际写入前复核。
5. 云端云状态的线下会话保护需要新增或复用“见面已结束”持久记录，不能用 DateApp 目前是否可见代替；本地也要同样校验。线下最后一次发言时间应参与互动锚点。
6. 只给「离开后消息」作闸；其他明确定时提醒、即时回复、角色自排具体承诺按已有语义运行。
7. 为这些集成点新增端到端测试：跨午夜、禁发期间、次日补发、主动发言后重置、线下见面跨夜、主动结束见面、通话、限额、关开开关和 Worker 旧版本兼容。

## 为什么不能只加提示词

上游新功能的云端任务使用 `expirePolicy: force` 且说明“到点必发”。仅写“夜间别发”进角色提示词不会阻止触发，也不会阻止云端消耗。必须在 worker 生成之前判断并执行 skip；本地也要避免重开页面时补发。
