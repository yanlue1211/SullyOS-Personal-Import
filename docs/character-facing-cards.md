# 角色可读卡片：角色视角契约（个人版）

本契约适用于**所有会发送到角色私聊、作为角色消息保存、注入角色上下文或进入原有记忆提取的系统活动卡片**，不仅限于写歌。

- **角色世界内的成果就是角色本人的行为**：角色写了歌、唱了歌、做了作品、玩了游戏、发了动态等，完成卡和私聊文本直接陈述「某角色完成了……」，以实际行为和结果为准。
- **不要在这些角色可读文字中暴露幕后的 AI/模型流程**：不说「AI 生成」「模型自动完成」「由系统生成」「海绵生成了一首歌」「机器合成」「调用某接口后获得」等，也不用「实际上这是角色自己做的」来强调或解释。
- **技术透明度只放在用户操作界面**：用户仍应看见服务商、生成按钮、积分消耗、任务状态、失败信息、密钥配置等真实技术细节，不能为了角色视角隐藏真实成本或错误。
- **事实与归属要准确**：只有系统确认成功后才写对应的完成卡。歌词定稿、歌曲演唱完成是两个不同事件；不可把歌词定稿写成已演唱，也不可把失败任务记成完成。
- **保留可核对的内部标记，不要把标记写进角色可读正文**：taskId、模型名称、provider、内部去重键可留在结构化数据中，不出现在给角色的自然语言内容里。
- **不要全局改写用户亲自发送的内容**。本契约约束系统生成的角色活动卡片文案与其注入上下文的正文，不清洗用户引用、技术讨论或保存过的历史原文。
- **消息继续走原有历史与记忆管线**：不另做一套记忆注入、提取或压缩逻辑，不删除旧卡片，只对未来事件使用新表述。

## 写歌的约定

- 歌词定稿：`🎵 歌曲完成卡 ·《歌名》\n角色名完成了这首歌。`
- 有声音频完成：`🎤 演唱完成卡 ·《歌名》\n角色名已完成这首歌的演唱。`
- 海绵、MiniMax Music、ACE-Step 均沿用该自然语言模板；后台仍分别维护真实的媒体文件、任务状态、音频版本、花费与失败处理。
- 成功音频按**独立录制版本**去重，歌词定稿卡与演唱完成卡各自保留。保存卡片时歌曲记录和消息同一 IndexedDB 事务提交；若未确认成功，不发送完成卡。
