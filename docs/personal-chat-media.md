# 个人扩展：聊天媒体

基于 `personal/audio-listening`，功能分支 `personal/chat-media`。

私聊输入栏上方新增「语音 / 虚拟图片 / 视频」。真实录音最多 120 秒，支持停止、试听、重录、发送。关闭面板、切换角色、退出组件时停止采集；异步麦克风授权返回后若会话已退出，立即释放媒体流。

录音先转为 16kHz 单声道 PCM WAV，保存进现有 blob_assets；消息类型为 `audio`，content 为 blobref，metadata 保存 duration/fileName。使用现有整包二进制备份和孤儿引用扫描，不把 object URL 写进数据库。纯文字导出只保留说明。

对话构建使用已有音迹 audioApi 配置，调用 materializeAudioDescriptions。识别结果写回 audioDescription 并缓存；主模型只接收转写与声音说明。未配置/失败时只提供「尚未识别」，不得推测用户原话。录音本身仍可回放，下次构建可重试识别。该配置来自现有设置，不另存密钥。

虚拟消息继续使用 text 类型，内容为 `[[虚拟图片:描述]]`、`[[虚拟视频:描述]]`、`[[虚拟语音:文字]]`。无数据迁移；原始文字备份可保留完整内容。char 的输出指南随聊天系统提示注入，分段器保护多行卡片为原子块，消息视图用同一组件呈现 user/char 卡片。虚拟视频不包含真实视频文件；虚拟语音是可展开文字的模拟语音条。

核心接点：Chat.tsx（入口和发送）、MessageItem.tsx（呈现）、chatParser.ts（原子分段）、chatPrompts.ts（输出规则和历史）、chatRequestPayload.ts（音频识别）、types.ts（audio 类型）。实现集中在 features/personal/chatMedia。合并上游时保留这些小接点。

验证：媒体格式经 sanitize 后仍可解析、多行卡片不拆开、WAV 头和 PCM 边界正确、音频引用不泄漏到主模型、切换会话释放麦克风、退出后迟到授权释放麦克风。还需真实设备验收麦克风权限、录音回放和当前音频 API 的实际识别。

## 用户录音批量清理

同一入口旁的「录音管理」可筛选当前聊天或所有聊天，逐条勾选、全选，或只选已识别录音。列表显示条数、时长、体积、时间及识别摘要；未识别条目会提示清理后无法再识别。需点击确认才执行，默认不勾选任何录音。

只更新 user/audio 消息：保留 ID、时间、已识别文字和其他 metadata，标记 audioCleared，并移除该条消息对录音的引用。事务提交后，按维护锁保护下的全量分页引用扫描删除未被其他消息、收藏等引用的音频。扫描失败则保留所有文件，删除失败的文件可后续通过现有资源清理回收。角色语音、虚拟媒体不受影响；当前聊天在清理后刷新。每次只删除已选且内容引用未变化的消息，过期选择不会清掉替换后的文件。

16kHz 单声道 16-bit PCM 每分钟约 1.92 MB（十进制），两分钟约 3.84 MB。持久化音频不等于全部解码常驻内存；清理界面按分页读取元数据和 Blob 大小，不批量解码音频。实际可用容量取决于设备、浏览器配额和其他已有资源。

## 通话真实录音与视频静音旁白

语音和视频通话的输入区新增独立「录制真实语音」，保留原来的打字和 STT 填入文字入口。录音可试听/重录，发送前用音迹音频 API 转写并分析声音，不修改正在输入的文字草稿；无配置或识别失败保留录音供重试，不发送猜测文本。保存为 user/audio 消息并标注 source=call，历史与记录页能回放；同一录音管理器可清理。停止角色播放后再采集，采集/识别期间禁用冲突输入及沉默主动接话；面板卸载或挂断使迟到识别结果失效。

视频旁白用 `<旁白>…</旁白>` 与台词穿插显示，使用衬线斜体和「旁白 · 不朗读」标签。批量 TTS 的公共入口与逐字 SSE 朗读器都剥离闭合或未闭合旁白，重播/收藏复用相同合成入口；拟声词和当前引擎声音标签不剥掉。语音通话固定禁止旁白，模型错误输出旁白块时额外移除。

固定协议集中在 format.ts/callFormat.ts：虚拟媒体与虚拟语音、录音理解/未识别/清理历史、通话录音、视频旁白、语音通话无旁白。通话仍使用 ContextBuilder.buildCharacterContext，不自行拼世界书。旧 TTS 提示词与拟声词配置继续保留。

发布使用现有 personal/audio-listening → GitHub Pages 工作流，增加媒体回归检查和构建内存上限。personal/chat-media 分支验证通过后合并，Pages 保留历史构建资源，不注销 SW 或清空用户数据库。个人版版本号为 v3.15-personal.1，触发正常版本更新机制。

## 媒体界面调整（personal.2）

加号第一页提供两个直接入口：「语音」直接打开真实录音页，右滑或点击标签切到虚拟语音输入；「图片／视频」直接打开虚拟图片描述页，可切换虚拟视频。协同工作与日程/情绪移到第二页。聊天输入框上方不再显示混合媒体和清理按钮。

麦克风支持指针/键盘按住录音，松开结束，试听后手动发送。等待权限期间若已松手或界面退出则释放麦克风，不延迟启动采集；取消指针也立即释放。语音清理移至全局设置的「录音存储」，和 API 配置为同级板块。

通话底部原翻译按钮改为真实语音/原生识别切换，记住用户选择，打字一直保留。翻译字幕默认为关闭，可在通话偏好开启，朗读语种也移到偏好。视频旁白不再显示“不朗读”说明，仅保留衬线斜体；所有过滤继续生效。

用户录音识别新增固定 system 协议，返回独立 transcript/analysis JSON：逐字原语言字幕不含语气、背景声或“用户说”等说明；分析单独保存。聊天/通话正文只显示字幕，分析位于默认关闭的「声音细节」。旧录音仅在带有明确原文/转写标签时恢复字幕，否则把旧说明留在折叠区，不猜测用户原话；不会自动重新识别已存录音或额外调用付费 API。角色上下文继续接收完整识别材料，清理保留字幕与分析。

## 识别编辑、心声和独立日程（personal.3）

长按用户语音卡片或通话声音细节可编辑原文字幕与语气/背景声。只改 metadata，不替换 content 中的音频引用、消息 ID、时间或已清理标记；audioDescription 同步重建供上下文读取。audioTextEdited 防止尚未完成的识别覆盖手动修正。编辑事件刷新聊天、通话和记录页，并标记云端对话快照需要更新。

角色每轮在同一回复内返回 `<心声>` JSON，字段 state/thoughts/undercurrent；角色虚构内心描写与模型推理严格分开。客户端剥离协议并把一份数据附在本轮消息 metadata；心声小按钮默认收起，弹窗显示状态、内心、可为空的暗流。主历史构建把心声作为未说出口、用户未必知情的角色材料加入上下文，不假装它是已说出的台词。通话普通/流式语音先剥心声，闭合和未闭合块都不朗读。旧消息不事后编造心声。API 格式不合规时不展示原始心声协议，不额外调用付费模型补写。

日程和情绪使用独立菜单与设置。新角色情绪默认关闭；旧角色先保留原来有效状态，用户切换日程或保存独立情绪时分离配置，避免把旧默认 enabled 误当成新授权而突然调用情绪 API。开启/关闭日程不再强制开启或清空独立情绪。

日程按角色当地日期缓存。跨标签页原子占位与同页 in-flight 合并确保每天首次自动生成只请求一次；缺 API 配置不占次数，失败也不自动重复扣费。已有当日日程不因刷新、改风格或旧重生成入口而再请求，风格次日生效。默认上下文包含全天初步计划，明确不是已发生事实、硬性时刻表或对用户的要求；不再以日程预制的时段独白代替当轮心声。保留手动编辑日程、当天已有安排与历史数据。
