# 个人新增功能：备份导入导出排查

检查对象：个人版聊天/音频/分享/心声、日程、模拟商城与个人日记，以及开发中的造物间。
检查方式：实际存储位置 → 完整/文字/媒体导出 → ZIP 分片/Blob → 导入 → 原功能重新读取；结合相关界面与协议回归测试。不会把仅有源码检查的项目称为完整 UI 端到端验证。

## 本轮发现并修复

1. 家园使用 `appRules: ''`，旧判断按真假值处理，误带了普通聊天的心声、回应状态、虚拟媒体输出要求。改为判断是否显式传入 App 规则；家园不要求生成这些标签。普通聊天继续有心声，已经保存的心声历史仍可按原规则读取/总结。原家园提示词比较的 8 项测试全部通过。
2. 淘宝/美团的 `personal_commerce_v1` 已随完整 assets 备份，但未登记到文字资源白名单。本次补入目录、订单、接入角色、偏好和已发送通知状态；媒体补丁不能覆盖它。
3. `personal_schedule_once:<charId>:<date>` 同样补进文字备份。它防止恢复后同一天重复自动生成日程、重复请求 API；完整备份原本已有。
4. 音迹旧 `sully_song_sound_v1_*` localStorage 缓存原本只在打开档案/再次听歌时迁移，直接备份可能漏掉。完整/文字导出前先执行纯本地迁移，再读取档案，不调用模型。
5. 老文字备份不知道新增商城/日程资源。恢复活动资源时，缺少新增个人资源不再解释为删除目标设备的数据；有相应记录时照常恢复。旧活动资源仍沿用既有替换规则。

完整备份能带走已保存的媒体字节；纯文字备份不承担本地录音或图片文件。外部图片/视频链接原样保留，不等于已把远端整段视频下载入备份。可重新生成的普通 TTS 缓存沿用原版策略，收藏语音另有原来的二进制备份通道。

正在录音、正在发送、倒计时、识别中等界面临时状态不作为已保存内容恢复，也不会据此自动重新录音/付费调用。没有恢复已经由用户删除的听歌日记功能；这次未修改 Rerank、Embedding 或现有后端。

## 造物间本轮后续功能

- 聊天加号和造物间 App 使用同一个按角色保存的联动开关。
- 开启时只给正常聊天自己的作品简介和用户明确分享来的信息，不装载完整源码/编程工具，不读取其他角色的目录。
- 模型自然提出灵感时先写灵感箱和邀请卡，不立即生成代码；可搁置、继续，发布后标记完成。
- 用户选择正式作品及接收角色分享，保存固定版本的白名单快照。分享卡不等于收藏。
- “询问 TA 是否收藏”只发送正常用户询问。Char 明确返回接收动作，且事务内仍有权限，才创建独立作品/版本并发接收卡。不能用口头“好看”推断收藏。
- 副本保留原作者/来源，进度清空；不复制私人交流、记忆、API 配置。原作品更新或删除不影响已分享的固定快照。
- 收到的分享可先在独立沙盒预览；预览进度只在本次内存中，不写原作者进度，也不产生虚假的聊天互动记录。
- 共享卡片、灵感卡与接收卡沿用同一聊天/上下文/记忆格式化和备份机制。控制 JSON 不进入公开气泡、流式预览或通知。

仍保持开发草稿。真实浏览器/移动端沙盒与 CPU/网络边界仍待验收；现有 iframe/CSP 不等于绝对进程/网络隔离。主页完成通知、单组件独立导入导出及自动运行测试工具仍待完成。
