## 三个核心模块

1. 作品服务：负责作品、不可变版本、草稿、进度、灵感、创作交流、分享快照和投递队列。
2. 沙盒运行器：只接收已发布的指定版本和该作品的进度，通过宿主受控接口交互。
3. 聊天事件桥：把已确认的操作转成结构化事件、可读消息和卡片；负责幂等投递和界面刷新。

模型只是提出操作的调用方。归属判断、开关校验、代码发布、复制、写进度和发事件由宿主执行。模型文本写“已收藏”本身不能触发复制。

## 数据模型与事务

在同一个 SullyOS IndexedDB 中分阶段增加以下表，不单开数据库。当前已落地 works/versions/drafts/states/events/turns/shares 七张表；其余在对应功能阶段迁移。

| 表 | 主键 / 主要索引 | 内容 |
| --- | --- | --- |
| workroom_works | id / charId | 名称、简介、归属、来源链、当前/稳定版本指针、状态 |
| workroom_versions | id / workId | 不可变 HTML/CSS/JS、状态 schemaVersion、父版本、测试结果 |
| workroom_drafts | workId | 草稿、baseVersionId、开发目标、待办、最近错误 |
| workroom_states | [workId,schemaVersion] 的 JSON 键 / workId、charId | 每种状态格式独立保留 JSON 进度和 revision；回退旧代码时读取旧格式 |
| workroom_ideas | id / charId | 灵感及讨论状态 |
| workroom_threads | id / charId、workId | 创作会话与可恢复任务位置 |
| workroom_turns | id / charId、workId、[workId,createdAt] | user/assistant 自然交流、当时作品名、投递状态和 messageId；代码只放在草稿/版本 |
| workroom_shares | id / recipientCharId | 固定版本的可复制内容白名单与来源；不包含原作者私有状态 |
| workroom_events | eventId / charId、workId | 经校验的原始互动、合并批次、待投递状态、宿主通知状态 |

所有读写服务显式传 charId，校验 work.charId；不要依赖界面当前选择的全局变量。

发布作品：版本、正式指针与完成事件在同一事务提交；后续通知阶段再增加通知待办。聊天消息由持久化待办补投，提交失败不显示完成。收藏：先校验接收对象和固定 shareId，再在同一事务创建新作品、新版本、干净初始状态、接收事件；shareId+接收角色的唯一标识防止重试复制多份。

投递采用持久化 outbox：读取待发事件或交流 → DB.deliverWorkroomPending 在同一个 characters/messages/assets/来源表事务内检查归属与开关、按 deliveryId 查重、保存消息和投递状态 → 提交后刷新界面。中途退出可重试。消息与标记不可出现半成功；水位镜像仍走原有清理规则。用户主动删除聊天后，已完成的 outbox 不重新生成已删记录。

合并高频事件必须在写聊天前完成。记录 actionId、起止时间、数量、原始事件 ID 和最终重要状态；跨角色、跨作品、跨会话不合并。已投递消息不可持续改写，否则可能在记忆水位后修改已提取的事实。界面退出、运行器关闭、切换角色及应用重新启动均触发待办检查；联动关闭期间只保存运行记录，不积压等待日后自动刷屏的聊天卡片。

## 卡片和记忆是同一份事件的两个出口

五类卡统一使用 Message.type=`workroom_card`、metadata.workroomEvent.version=1，kind 区分 inspiration/completed/progress/shared/accepted。

每条保存事件发生时的角色名、作品名、简介、原作者和行为正文。完整代码、运行状态、API Key、私人开发聊天不进入卡片 metadata。作品 ID 供打开定位；正文不依赖实时查作品。原作品删除后，聊天文本依然可读；点击打开说明资源已不存在，不删除旧消息。

普通上下文、宫殿提取、手动区间总结、旧版归档都调用共享格式化器。联动开关只控制新能力和新自动事件，不控制历史消息格式化。不为确保记忆而额外请求模型或直接强写长期记忆。

事件正文是引用材料，不能解释为工具命令。游戏里的动作明确来自组件，不冒充现实发生的动作。分享与接收分成两条事实。事件序列化仅采用白名单字段，未知版本、角色不匹配的快照不得退回原始 JSON 或源码。

需要额外验证：UI 列表/预览/引用/搜索、云端即时聊天及后台已有历史组装不能把新类型丢弃。当前的格式化测试不等于这些入口或完整备份已验收。

## 创作请求：共享完整管线，隔离执行权限

每轮从数据库读取角色最新档案、有效原文范围与水位快照，使用 buildChatRequestPayload，并传 appPrompt（创作规则、本会话消息和当前开发任务）。核对其实际最终请求，不能仅因为用了 ContextBuilder 就宣称召回齐全。

加入明确的 workroom recallEntryPoint；审查 trace、召回策略和当前只为 chat_app/home_3d 启用的条件。需要的上下文按正常生效规则进入；聊天专属音乐/商城工具不要因复制参数而意外变成创作执行权限。

创作交流保存在独立会话。重要讨论/决策以完整的自然语言 user/assistant 片段或明确定义的创作事件进入共享历史，使用稳定来源 ID 去重；代码、调试日志、工具结果不镜像。不能只保存“完成了作品”而丢失用户在讨论中表达的重要偏好。后续请求避免把已镜像对话重复追加两次。创作历史也不能成为绕过正常聊天可见范围的后门：公共聊天只读有效范围，创作会话按自身已明确显示的历史规则加载。

代码按需读取，仅加载当前作品所需版本；目录分页/限量并标注未列全，不把截断误报成“没有其他作品”。正常聊天目录只含当前 Char 自己的作品 ID、名称和一句简介。

能力表：

| 场景 | 允许 | 禁止 |
| --- | --- | --- |
| 正常聊天，联动关 | 理解历史卡片 | 新灵感协议、实时目录、自动收藏 |
| 正常聊天，联动开 | 当前角色作品目录、灵感、推荐自己作品、明确收藏分享 | 读/改源码、测试、其他角色目录 |
| 造物间 | 当前角色创建、按需读代码、修改草稿、测试、发布/回退 | 任意宿主源码、其他角色私人上下文 |
| 组件沙盒 | 当前实例状态、经校验的互动事件 | 模型 API、宿主数据库、任意通知/聊天写入 |

每次工具执行重新检查角色、开关、请求代次和操作来源；开关关闭、角色切换或请求取消后，旧请求不能继续操作。工具循环设上限与可取消；失败保留草稿，不自动无限调用 API。

## 分享与收藏

用户从原作者作品选择分享，宿主冻结该正式版本。分享卡只让接收角色读到名称、简介和来源，源码留在 workroom_shares。原作者以后更新或删除，不改变已分享的副本内容；分享自身删除/失效则明确告知不可收藏。

按钮文案为“询问 TA 是否收藏”；它发送询问，不替 Char 接收。联动开启时模型返回明确的 accept_share(shareId) 意图；宿主成功复制后才发 accepted 卡。只有“好看”“以后看看”等自然语言不自动执行。联动关闭时按钮不开放自动收藏，也不加载收藏协议。

复制白名单：HTML/CSS/JS、必要静态素材、功能说明、原作者和来源链。默认重置进度与开发草稿；不复制聊天、记忆、凭据、私有运行数据。依赖私人素材或状态的作品先明确缺失项，不悄悄带走。Char 可在造物间修改自己的副本。

## 沙盒与测试边界

使用 iframe sandbox=allow-scripts，不加 allow-same-origin、表单、弹窗、下载或顶层导航权限。srcdoc 的首段 CSP 由宿主产生：默认拒绝外部资源，允许必要内联代码及受控本地素材；禁止 connect、frame、object、form、base 等通道。首版组件不提供网络或宿主 API 调用权限。CSP 本身并不保证绝对安全；必须验证导航、子框架和各种资源通道，不能仅靠代码关键词扫描。

受控 MessageChannel 只初始化到本次 iframe；核对 event.source，绑定随机会话、版本、workId、charId、接口名及请求 ID。沙盒传来的角色/作品 ID 不作为授权依据。重载即废弃旧通道；限制消息大小、JSON 深度、频率、状态容量、事件数量。接口响应采用明确成功/失败和幂等 ID。

saveState/loadState 只访问当前作品状态；emitEvent 只记录组件内事件，不执行工具；notify 只产生组件内通知，不得冒充新作品完成；requestUpdate 仅新增开发待办，不直接调用模型或发布。

版本先保存草稿 → 隔离运行与错误收集 → 明确发布。脚本加载、接口往返、状态读写能自动测试；游戏规则和界面质量需要实际交互验收。测试失败不覆盖正式版本。iframe 不是可靠的 CPU 隔离；错误/超时处理和“停止运行”不能被宣传为能强制终止所有死循环，移动端要专门验证。

## 版本与状态兼容

正式代码不可变，编辑生成新草稿。发布使用 baseVersionId 比较，防止并发覆盖。回退正式版本与游戏进度分开处理。

状态携带 schemaVersion 和 revision；兼容时沿用。需要迁移时在沙盒中给旧状态副本运行迁移，再做大小/结构校验，成功才原子更新版本指针与状态。失败保持旧版旧进度。保留迁移前状态快照，不能盲目把新 schema 的进度传给旧代码。首次发布前只允许可信宿主能力，沙盒无权直接读取别的版本状态。

## 完整备份与独立导出

新增表同时登记 DB 升级、FullBackupData、DB.exportFullData、OSContext 分片导出和恢复映射、DB.importFullData、清理/角色删除边界。导出从一致快照读取，避免版本指针指向未导出的版本；大代码/版本分页处理，不一次装入全部内存。

完整备份包括版本、状态、灵感、会话、分享快照、来源链、原始事件、通知和投递状态。恢复保持内部 ID 和关联，校验孤立引用与归属。旧备份无此模块时遵循原恢复模式，不能无条件清空新数据；媒体补丁不能替换文字、源码和进度。文字备份如何处理内嵌图片与代码需专门实现，不能对代码串粗暴剥图后宣称组件完整。

独立导出用版本化作品包；默认不导出私人进度、聊天和开发会话。导入分配新本地 ID、保留来源，作为未运行作品，验证后才允许打开。备份恢复不自动运行导入代码，不重复发送已投递通知/卡片。导入失败尽量在写库前发现；不可恢复数据不静默丢弃。

## 分阶段交付与验收门槛

1. 本次：架构及事件格式化契约；测试五类卡聊天/宫殿/手动归档入口一致、快照及角色边界。尚不合并到日常使用分支。
2. 数据与运行器：作品 CRUD、独立角色、版本/状态、沙盒、完整备份往返先落地；恢复后可继续游戏才算完成。
3. App UI：作品库、灵感、交流、管理、深链和通知，事务提交后即时刷新。
4. AI 创作：完整共享请求管线、受限工具循环、草稿/测试/发布、重要交流进入共享历史。
5. 日常联动：独立开关、轻量目录、灵感/完成/进度卡、合并与 outbox，关闭后历史不变。
6. 分享收藏：固定分享包、询问按钮、模型明确接收、独立复制和来源记录。
7. 总验收：跨角色隔离、备份恢复、旧备份、重复投递、关闭重开、并发发布/迁移失败、页面不切换即时刷新，以及音迹/商城/语音/心声/自动回复回归。

每阶段的开发结果进入同一独立分支和草稿 PR，达到验收门槛后再纳入日常使用版本。不增加 Worker、D1、GitHub 模型权限或新的持续后台任务。

## 本轮实现说明与待验收项

- 草稿使用 revision+baseVersionId 防止并发覆盖；发布新版本不自动运行作品。
- 同格式更新沿用进度。切换状态格式必须显式提供初始/迁移结果；不会猜测转换规则。旧格式进度保留，回退不把新格式进度强塞给旧代码。
- 组件通过 window.workroom 的异步 API 操作。宿主端口绑定固定角色、作品、正式版本；序列号去重，排队写入，撤销后取消尚未开始的操作。已进入数据库事务的写入仍可能正常提交，停止运行不是回滚已提交进度。
- 原始事件每作品上限 10000，接口每 10 秒最多 60 次。单个状态限制 256000 字符、嵌套 40 层；各代码字段限制 500000 字符。到达上限明确报错，不静默删旧数据。
- 不支持临时 blob/blobref 代码资源或状态；首版用内嵌 data 素材，保证导出可迁移。文字备份保留代码字符串（包括其内嵌素材），不对源码递归剥图。
- 流式导出七表共用一个 readonly 事务，各表分别分片；恢复七表共用一个 readwrite 事务。显式空模块表示清空模块，旧备份缺模块表示不动现有模块；媒体补丁不替换源码或进度。角色删除同时删除其模块数据，聊天卡片的历史快照独立保留。
- 当前版本的运行器已做协议和宿主/真实 IndexedDB 集成测试，App/消息组件已做 jsdom 交互验证；真实浏览器测试尚未完成。当前执行环境未预装 Chromium，尝试安装返回的压缩包不完整，因此不得宣称已通过真实浏览器安全与移动端验收。
- CSP 和 iframe sandbox 不是绝对网络/CPU 隔离：不授权 fetch、外部资源、同源、父窗口导航等；浏览器仍可能允许 iframe 自身导航。运行器发现再次 load 后撤销端口，不能把这描述成阻止首次导航请求。上线前需要真实浏览器逐项验收，并向用户明确能力边界；不能靠额外 CSP 标签或字符串过滤声称彻底解决。
- 仓库全量 tsc 当前有大量既有诊断，不能宣称全库类型检查通过；新增造物间文件单独做语义诊断，相关回归测试与生产构建另行记录在 PR。

## App 与 AI 创作阶段的具体行为

- 桌面新 App 注册在 PhoneShell 和按需预加载表；首次进入显式选择 Char。作品、交流、运行、草稿和版本按同一稳定角色/作品 ID 切换。
- 创作请求先接收既有收件，再保存/投递本轮用户消息；从 DB 加载当前角色真实可见范围，使用同一水位快照和 buildChatRequestPayload，recallEntryPoint=workroom。空范围或已移出范围的重试不能伪造新消息 ID 绕过边界。
- 用户/角色的自然交流进入 workroom_turns，并以同角色普通文字消息写入共享聊天；完整源码只保存在 drafts/versions。近期创作交流不再重复附加第二份历史，也不强行重读已归档全文。
- 正常创作一次模型调用；只有模型明确 read_code 时，提供当前作品草稿或正式代码再续答一次。不读取其他作品代码，不额外调用模型判断灵感，不自动循环请求。
- 角色 API 沿用 resolveDialogueApi；safeFetchJson 沿用已有原生/兼容协议、错误处理和调用记录。本轮完整输出校验后，草稿与角色自然回复在同一事务保存，格式错误/截断不覆盖旧草稿。
- 用户切换角色、返回或停止时撤销请求；迟到结果不能写入新角色或跳回旧页面。草稿编辑器维护独立修订基线，自动刷新不会覆盖未保存编辑，发生并发修改时明确拒绝保存。
- 完成卡和互动卡由实际保存的事件生成，不能由模型一句“完成”伪造；系统作者卡片在通用 system 文本分支前渲染，隐藏系统日志也不隐藏这类卡。卡面保持单层样式边界，并可定位回对应作品。
- 游戏互动记录开关已与聊天加号的完整联动开关统一。关闭只停止新的自动互动投递，已保存记录仍参与上下文和记忆；完成卡及创作交流不靠此开关过滤。
- 新增历史提交事件会即时刷新 ChatApp，并触发现有宫殿缓冲处理；是否请求提取、是否形成记忆，仍遵守原维护模式、水位和重要性判断。失败保留原文等待既有重试，不直接强写长期记忆。
- 备份包含创作交流及 delivery/messageId。v75 备份缺少 turns 时按空交流表兼容恢复；完全不含造物间模块的更旧备份保留现有模块。已投递记录恢复后不再重新投递，媒体补丁不替换文字/源码/进度。

## 本阶段验证结果

- 造物间、完整备份、消息展示/可见性、角色上下文、心声和 App 预加载的专项测试另见 PR 验证记录。
- 家园专用规则使用空字符串时的公共提示词判断已修正；家园不生成心声，普通聊天保留原协议，8 项家园上下文回归全部通过。
- 待发队列使用 [charId,delivery] 索引，只加载 pending 记录，不在每次组件事件时扫描全部已投递历史。互动引发的交流刷新也不重新读取全部旧版源码。


## 本轮修正记录

原 homeChatPipelineParity 测试确实暴露空字符串 appRules 被误作未设置的问题，造成家园误带心声等聊天输出协议。本轮修正公共条件，家园不新增心声生成要求，原8项家园测试已全部通过。此前仅把它记录为基线差异不够完整。普通聊天的既有心声历史/记忆规则保持。

本轮的商城等个人功能备份排查和修复详见 docs/personal-backup-audit.md；旧版音迹数据在完整/文字导出前本地迁移，商城与日程标记补入纯文字白名单。
