### 特别核实

1. 原哔哔仍有 `publicFeed=true` 的公开化迁移。新朋友圈若共用这份状态，独立权限会被破坏。因此采用新命名空间和新表，不复活旧 `circles` 作为私人圈。
2. 原哔哔 `projectFriendPost` 主要隐藏未识别账号的主人身份，**不是共同好友互动可见过滤器**。
3. 原哔哔评论动作以 `comment` 承载，回复通过 `replyToCommentId` / `replyToSourceCommentId` 表示；关注可在 `follow` 或附带 `followAuthorId` 中出现。公众人物校验必须检查这些附带动作，不能只检查顶层 kind。
4. 核查的哔哔动作落库枚举是 post/comment/none/repost/follow/unfollow，未在该枚举发现点赞或私信动作。实施前仍需搜索 UI 和其他入口；没有的能力不为了“限制”而补造。
5. 原图片浏览大多仍提供文字材料及配图数量，不意味着所有角色已看过真实像素。视频能力是抽帧理解，不自动包含视频声音。
6. `isMessageSemanticallyRelevant` 接受具有可读正文的 `_card`，系统角色消息并非一律排除。自动提取调用 `formatMessageForPrompt`，聊天/角色页手动归档使用 `formatMessageWithTime`。这证明可以复用管线，**不等于尚未开发的朋友圈卡片已经通过记忆验收**。

## 3. 总开关与界面补充（用户最新要求）

- 朋友圈设置采用原生设置的分组列表与开关样式。
- 顶端“开启朋友圈”，默认 false。用户确认开启后，才展示好友、角色、行为、预算和日志设置。
- 未开启时不挂自动巡检，不构建朋友圈提示词/见闻，不进行朋友圈模型请求；App 入口可进入简洁启用页。
- 再次关闭停止新的活动；撤销正在等待的工作，迟到结果不能写入。历史动态、浏览档案和已落库的聊天卡片保留；重新开启不重放整段历史。
- 首页参考两张微信截图：大封面、右下头像/昵称、白底连续动态、左侧方头像、蓝灰昵称、紧凑媒体宫格、浅灰互动区、时间右侧“…”展开赞/评论。滚动后显示紧凑标题栏。

## 4. 数据和权限设计

采用主 IndexedDB 的独立 `moments_*` 表，模块位于 `features/moments/`。当前 DB_VERSION=78；实施建表时以当时最新版本递增，幂等创建索引，避免与其他工作分支抢占版本。

| 数据 | 建议主键/索引 | 用途 |
|---|---|---|
| 设置/配置 | 全局单例、characterId | enabled、好友关系版本、角色开关、稳定习惯、待确认习惯建议、预算 |
| 动态 | postId；createdAt；authorId+createdAt | 正文、作者、时间、主题、媒体、独立可见范围、修订号 |
| 评论/点赞 | interactionId；postId+createdAt；actorId | 独立互动、明确回复父 ID；点赞 actorId+postId 唯一 |
| 事件 | eventId/递增序号；目标角色+状态+序号 | 新帖、新评论、新回复分开处理，不重复扫描全史 |
| 浏览档案 | characterId+postId；characterId+browsedAt | 真实浏览时间、原文/摘要、已读互动事件版本、个人反应 |
| 见闻快照 | characterId | 保存最终注入文本、来源 ID、生成时间和权限版本 |
| 调度/请求 | 请求 ID；状态；角色+下次机会；设备日 | 租约、预算尝试计数、冷却、提交回执、处理游标 |
| 重要事件投递 | characterId+事件 ID；delivery 状态 | 与消息同事务提交或 durable outbox，防重放/漏投 |
| 活动日志 | 时间、角色 | 结果、跳过原因、错误；保留有界日志，不注入聊天/记忆 |

所有调用方只拿 `repository.projectPost(viewerId, postId)` 这类权限投影结果，统一在读取层完成过滤。不能先把整帖、全部评论交给模型，再请模型“别看”。

权限规则：

1. 本人可看自己的动态。其他人先满足当前双向好友关系，再判断 all/include/exclude/self。
2. 发布者可看本帖全部互动；互动本人可看自己的互动；其他查看者只看与自己互为好友的互动作者。
3. 回复还需要检查被回复评论/对象可见性。隐藏目标的名字、原话、引用、统计和“共有 N 条”不能从回复字段漏出；必要时隐藏整条回复，而不是偷偷展开隐藏评论。
4. friendIds 的 UI 选择只允许当前好友，持久字段保存 ID。角色改名不改变关系；角色删除不能改投同名角色。
5. 生成前过滤一次，提交事务按最新关系、开关、动态修订和请求版本再过滤。权限变化拒收旧响应。
6. 好友删除、可见性收紧等是权限变更事件，立即使受影响的见闻快照失效并重建一次；这是保证后续请求权限的必要事件，不是普通聊天每轮重排。已经形成的真实历史经历/聊天记忆不默默改写。

## 5. 活动调度与计费语义

- 五分钟只有一次轻量的到期索引检查。全局关闭时不挂定时器；页面隐藏/冻结时暂停，恢复后重新安排正常机会，不追补离线轮数。
- 一个全局持久租约防多标签页并发；单角色请求有 requestId/代次。单次 tick 限制发起数，失败退避，不循环清空积压。
- 自动目标 15–25 是全体角色的软目标，默认硬上限 30；不补量、不强迫发帖。发帖与浏览的权重分别来自习惯。
- 每日预算按用户设备本地日统一记账，角色活动时段按角色时区；不把不同角色的“今天”拆成多个全局额度。
- 调用尝试在即将发送前持久占额；发出后失败/格式无效也可能被提供方计费，保留次数。模型未调用的免费 tick 不计额。手动请求单列。
- 截图参考中的普通滚动/打开 App/点赞/本地发帖不需要模型；手动“让 TA 活动”和习惯评估等才产生相应模型请求。
- 媒体识别属于额外模型请求，不能藏在“一次活动一次 API”背后。尽量在用户发布准备时一次识别并缓存，明确显示媒体识别用量；自动链路不得绕过自动预算偷偷发识图请求。
- 一次活动只装配一个角色自己的上下文。可提交少量候选动态，每条先权限投影，再按总输入预算装配；未提交的候选不能算已浏览。
- 发新帖只创建事件；B 的互动只能在 B 后续活动中生成。同一请求可以浏览与互动已有候选，但不能代另一角色说话。
- `none` 是合法成功结果；成功接收材料但不互动也记浏览。网络/格式/数据库失败不写“已成功浏览/互动”，不消耗事件水位。
- 一次活动的浏览记录、互动、事件进度、快照与卡片投递状态一起提交，失败全回滚。API 尝试统计作为已发生费用记录独立保留。
- 每次发布提供最近十帖正文/主题，规则性校验拒绝明显重复；主题标签和文本相似度只能拦截明显重复，不能宣称完全识别语义复读。

## 6. 上下文、检索和记忆

- 快照在浏览/发布/互动/明确查看成功后更新，使用绝对时间，通常约 500–1500 Token。读快照不调用 LLM，不重新摘要、不写“刚刚/几分钟前”。
- 连续普通聊天对快照做精确字节相等测试；跨三天边界不在聊天里重排。通过单独到期维护事件更新一次快照，原浏览档案长期保留。
- 聊天明确查看在正常生成前执行授权读取，再记录实际浏览。纯“提到 A”不能变成自动浏览授权。无法确定对象/动态时自然澄清，不猜测并推进浏览水位。
- 连续话题保存按角色/会话隔离的 postId 和有效期。检索已看内容与新浏览分别记录；“有权限”本身不等于“已浏览”。
- 新卡片使用 `moments_card`，保存可读 content 和参与者视角数据，独立 source，接入 `MessageItem`、`ChatPrompts` 和 `normalizeMessageContent`。不借用 `friend_feed_card` 的哔哔文案。
- 重要卡片只给实际参与/实际得知的角色，不向“也有权限但没看过”的好友广播。快照与卡片都不能携带隐藏互动。
- 事件落库与消息投递幂等，提交后触发现有聊天刷新和自动缓冲检查；自动整理沿原阈值、手动整理沿原选择范围，关闭宫殿不自动启用。
- 验证必须捕获自动提取和手动归档最终 API 输入：参与者、事件、正文、互动、时间都存在，并且未获授权材料不存在。“数据库里有卡片”不是通过条件。

## 7. 哔哔公众人物模式的修改边界

- 在原哔哔设置中新增按角色配置的公众人物模式，旧数据默认关闭。
- 在哔哔账号关系层增加显式目标分类/公开互动许可。`known=true` 仅代表认得身份，不代表公众人物同行、公开互动合适或用户已允许。
- 配置面向账号，不把一个已确认主号的许可扩散到未知小号。微博绑定只是原帖归属，同样不自动获得同行许可。
- 统一 `canPublicInteract(actorAccount, targetAccount, action)` 供候选构建和落库使用；user、普通粉丝、未知目标拒绝主动互动，已确认且允许公开互动的同行才通过。
- 校验评论/回复的目标、帖子作者，以及附带关注目标；一批动作中出现不合规项不先落合法半批。本人发帖、读取公开讨论仍可正常工作。
- 特别核对 user 评论触发的即时回复路径，不能因“是用户先评论”就跳过公众人物模式。
- 新固定提示词仅注入哔哔请求/哔哔任务块。朋友圈好友不导出为公开平台许可。
- 公共发帖不能注入新朋友圈见闻或私人动态检索材料。现有哔哔请求本就使用角色本人背景/历史；公众人物提示词能约束表达，但程序无法仅靠目标身份校验判定自由正文是否语义泄密。不能把目标校验宣称为正文绝对防泄漏能力。
